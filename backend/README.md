# GuildHall backend

The API is an off-chain service for wallet sessions, commission records, escrow EOAs, and the searchable work index. It uses a separate EOA for each commission; the API encrypts those private keys before storing them in Postgres. The gas payer EOA funds transaction fees. There are no GuildHall on-chain programs or contracts.

The first server scaffold exposes `/health` for process liveness and `/ready` for Postgres and Solana RPC checks. Product routes, migrations, wallet sign-in, and commission escrow lifecycle handling are the next implementation steps.

## Local setup

```sh
cp .env.example .env
# Set DATA_ENCRYPTION_KEY to a fresh random secret of at least 32 characters.
docker compose up -d
bun install
bun run db:migrate
bun run dev
```

The web app runs at `http://localhost:3000`; the API runs at `http://localhost:3001`. Open `/health` and `/ready` on the API to check it. `bun run check` type-checks the service.

## Environment

Required for local readiness:

- `DATABASE_URL`: PostgreSQL connection string.
- `SOLANA_CLUSTER`: `localnet`, `devnet`, `testnet`, or `mainnet-beta`.
- `SOLANA_RPC_URL`: RPC endpoint for the selected cluster.

`PORT`, `TRUST_PROXY`, and `SOLANA_COMMITMENT` have local defaults. Add the supported `USDC_MINT` and `USDT_MINT` addresses for the selected cluster. The frontend server calls this API, so browser CORS configuration is not used.

The upcoming SIWS session flow will use `AUTH_DOMAIN` and `AUTH_URI` for the frontend origin (`guildhallai.com`). `AUTH_TOKEN_PEPPER` is for hashing opaque session tokens if that session design is selected. Encrypt commission EOA private keys and private commission data with a separate random `DATA_ENCRYPTION_KEY`. Scheduled expiry and reconciliation tasks will use `CRON_SECRET`. These secrets belong in the backend host's secret store and local `.env`, never in the browser bundle or Git.

The per-commission escrow private keys are generated by the backend and encrypted in Postgres with AES-256-GCM. Keep `DATA_ENCRYPTION_KEY` and the gas payer key in the backend secret store. The encryption key must be backed up securely; losing it makes escrow EOAs unrecoverable. Solana transactions and Postgres updates cannot commit as one transaction, so escrow actions use a durable, idempotent operation ledger and need reconciliation.
